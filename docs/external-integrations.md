# 外部 Agent、工具与操作接入

前端是任务与批准界面，通过同源 `/v1/*` API 访问本地后端。它当前不抓取互联网 Agent，不直接持有 RPC 密钥，也不会执行外部脚本。候选 `svc_primary` 与 `svc_backup` 来自 `src/config.js` 的固定配置。

## 当前可运行路径

浏览器 → 本地会话 / CSRF → 任务提案 → 人工批准范围 → 工作器 → 准入与单次调用网关 → SAMPLE 响应 → 固定区块验收 → 私有报告。

`GET /v1/integrations` 只返回能力目录、配置是否填写及实现阶段；不是探测 API，不发起网络请求，不返回完整 endpoint。页面中的“已有适配器”不表示 LIVE 已可用。当前模式下没有调用外部模型、RPC、OSV 或钱包。

## 实际接入渠道

| 对象           | 渠道                          | 来源与边界                                                                                         | 当前实现                          |
| -------------- | ----------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------- |
| 链上数据       | Ethereum JSON-RPC over HTTPS  | 管理员配置的 RPC，固定 chainId、地址、区块 hash；当前只允许 `eth_getBalance` 等必要只读方法        | 参考与候选适配器未联调；LIVE 阻断 |
| 工具服务       | MCP，计划使用 Streamable HTTP | 后端连接批准的服务器，用 `tools/list` 获取声明，批准后通过 `tools/call` 调用；工具声明是待验证输入 | 未实现 MCP 客户端                 |
| 外部 Agent     | 服务专用 HTTPS API            | 需要明确接口 schema、鉴权与权限；服务输出仍需验收。A2A 等通用协议可后续评估                        | 尚无通用适配器                    |
| Agent 发现     | ERC-8004 身份注册信息         | 注册信息提供身份与服务线索，不保证可用性、能力或信誉真实性；须进入本地准入                         | 尚未实现注册表读取                |
| 客户端依赖公告 | OSV API                       | 固定版本锁文件静态检查；不安装包、不执行第三方代码                                                 | 独立适配器已提供，未接入运行链路  |
| 证据登记       | EIP-712 + 自定义合约          | 需要独立签名器与单独发布批准；身份登记和证据登记是不同概念                                         | 合约草案未部署、未审计            |

“操作”应建模为受限工具调用：服务 ID、允许的方法、参数 schema、权限范围、预算、超时、结果 schema 和验收规则。当前只支持只读余额查询，不支持任意 URL、网页抓取、shell、转账或自动签名。

## 建议实现顺序

1. 完成两个候选 RPC 与两个独立参考来源的联调，验证 EIP-1898 固定区块、来源冲突和过期数据拒绝。
2. 对齐服务 manifest、客户端依赖和网络出口限制；加入超时、响应大小限制、禁止重定向与 SSRF 防护。
3. 对确定的外部 Agent API 或 MCP 服务添加适配器；由后端保存凭据，前端仅选择服务 ID 和查看批准范围。
4. 接入 ERC-8004 发现身份，再按本地准入策略筛选；不能把注册或评分当作通过结论。
5. 完成签名器、合约安全核验与链上回执后，再开放公共发布。

仅设置 `.env` 的 RPC 变量不能完成这些门槛，也不会打开 LIVE。
