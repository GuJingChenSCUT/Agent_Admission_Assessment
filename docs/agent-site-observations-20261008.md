買嘢幫公开客户端引用的流程包括 `/api/v1/session`、`/api/v1/tasks`、任务补答 `/answers`、确认 `/approvals`、继续 `/runs` 与停止 `/stop`。这些是读取公开代码得到的路径线索，本次没有对它们提交请求，也没有验证其生产授权能力。批准和购买等动作不可与只读测试混淆。

## 怎么调用，举一个准确的例子

1. 网站开发者提供一个受支持的能力，例如“只生成行程草稿”，以及 endpoint、鉴权、参数 schema、返回 schema、超时和费用。
2. 我们在后端写该服务的专用适配器，注册固定服务 ID 与允许的操作。页面不会直接拿网站首页去 POST prompt。
3. 用户提交要求；系统整理范围与验收标准，取得批准后，由网关调用适配器。
4. 保存实际请求与响应来源，按该任务的规则验收结果，返回页面。

这五个服务涉及运营、旅游、任务协作及购物，不能直接塞进现有的 ETH 余额验收器。需要独立的任务 schema 和规则，例如行程是否覆盖指定地点、是否超预算。HTTP 200、模型回答流畅或网站有“AI”字样，都不等于服务完成了承诺。

PI 在本项目拟承担的编排 / 模型角色，与这五个待测业务服务是两个接口层。具体 PI 产品仍待官方资料确认，见 [PI API 预留说明](pi-api.md)。
